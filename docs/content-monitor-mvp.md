# Content Monitor MVP

第一阶段只建立本地、可替换、可验证的数据闭环，不登录平台、不自动发布、不发送通知。

## 当前边界

- OpenCLI Admin 只负责发现公开作品、定时采集和保存原始数据。
- 同一作品首次出现时写入 `collected_records`；每次后续采集都写入新的
  `engagement_snapshots`，不再因内容去重而丢失互动数据变化。
- 统计检测器只执行确定性规则，不调用模型。候选作品必须同时通过绝对公开数据门槛和
  账号自身基线门槛。
- 内置 AI 和通知默认关闭；平台分析、二创和发布反馈不属于第一阶段代码路径。
- Docker 服务默认只绑定 `127.0.0.1`，中心 API 不挂载 Docker 控制 Socket。

## 数据表

| 表 | 用途 |
|---|---|
| `content_accounts` | 对标账号的稳定身份 |
| `content_works` | 作品稳定身份与首次/最近发现时间 |
| `engagement_snapshots` | 每次采集看到的公开互动计数及完整原始数据 |
| `detection_results` | 统计检测器的门槛、基线、倍数、证据与置信度 |

平台返回字段尚未验证，因此快照同时保存标准指标和完整 `raw_data`。确定首个平台后，再根据
真实返回数据补充字段别名、观察窗口和阈值，不在本阶段写死平台公式。
